# SVG Normalization Profile v1 — draft 0.1

[English normative text](svg-normalization-v1.md)

状態: 2026-10-18 時点の実験的な入力処理プロファイルです。英語本文を正とし、
MUST、MUST NOT、SHOULD、MAY は SPEC.md と同じ意味です。本書は全文の参考訳です。
汎用の CSS サニタイザーでも safe-svg-v1 の拡張でもありません。

改訂（2026-10-28、Issue #3）: `letter-spacing` を第3節のプロパティおよび
safe-svg-v1 の属性として認め、曲線（Cセグメント）の marker-end ホストを
第3.1節の接線規則のもとで認め、第3節で受理する font-family の名前形式を
明確化しました。本参考訳にも同じ改訂を反映しています。

## 1. 目的と互換性

正規化実装は、限定された CSS 付き SVG を [safe-svg-v1](safe-svg-v1.md) に適合する
SVG に変換し、その後に書き込み実装が埋め込みます。出力プロファイルを緩めては
なりません（MUST NOT）。PNG wire v1、`vector-png.svg`、圧縮・抽出規則は不変です。
正規化は明示的なインポート操作であって抽出ではなく、元のバイト列は変更せず（MUST）、
正規化後の SVG だけを埋め込みます。プロファイル識別子や変換レポートは保存形式に追加しません。

## 2. 変換・描画前の検証

入力は厳密な UTF-8 XML（BOM と UTF-8 宣言は任意）で、SVG 名前空間の svg ルートが
1 つでなければなりません（MUST）。正規化実装は描画前に、DTD、実体宣言、外部実体、
XML 宣言以外の処理命令、スクリプト、イベントハンドラー、アニメーション、異なる名前空間、
画像、use、foreignObject、外部リソース、未知の要素・属性を拒否しなければなりません（MUST）。
変換前後の描画も含め、ファイル・ネットワーク取得をすべて無効にしなければなりません（MUST）。
未検査のソースをブラウザー DOM に挿入することは禁止します。上書きされる宣言、
一致しない宣言、未使用の定義内の宣言もすべて検証しなければなりません（MUST）。

入力で許可する語彙は safe-svg-v1 に、style 要素、制限付き marker 要素、名前空間なしの
class／style／marker-end／role／aria-* 属性、第3.1節のマーカー定義属性を加えたものです。
style 要素はルートまたはルート直下の defs の直接の子で、CSS テキストのみを含み、
任意の `type="text/css"` 以外の属性を持ってはなりません（MUST）。入れ子の svg ルートは未対応です。
ID とローカルリソースは、参照先の型、ID の一意性、リソース定義内の参照禁止を含め、
safe-svg-v1 に従わなければなりません（MUST）。ただし第3.1節で明示的に対応する
marker-end の参照先は例外です。アクセシビリティ属性は実行不能な
メタデータであり、実行する指示として扱いません。

基準上限は、メモリ確保前と解析中に適用しなければなりません（MUST）。入力・出力は各
1,000,000 UTF-8 バイト以下、要素数 5000 以下、深さ 32 以下（ルート 0）、属性あたり
100,000 コードポイント以下、style 要素・属性を合計した CSS は 100,000 UTF-8 バイト以下、
セレクターは 1000 以下、宣言は 10,000 以下です。ビューポートは一辺 4096 ピクセル、
合計 4,000,000 画素までです。より厳しい制限やローカルで明示的に引き上げた制限は
文書化し、`resource-limit` と形式不正を区別しなければなりません（MUST）。
解析・照合・描画には有限の時間・メモリ方針が必要です（MUST）。
サブプロセスのタイムアウトだけでは OS サンドボックスになりません。

## 3. 閉じた CSS サブセット

基準では規則リストとインライン宣言リストを受け入れます。空白と CSS コメントは許可します。
セレクターは、大文字・小文字を区別する SVG 要素名、`.CLASS`、`#ID` のいずれか 1 つ
でなければなりません（MUST）。セレクター内の CLASS・ID と class トークンは
`[A-Za-z_][A-Za-z0-9_-]*` に一致しなければなりません（MUST）。
これらをカンマ区切りのリストにできます。結合子、複合セレクター、全称・属性・疑似セレクター、
名前空間付きセレクター、エスケープ、入れ子、すべての at-rule（@import、@font-face、@media を含む）、
カスタムプロパティ、一括指定プロパティ、`!important` は拒否しなければなりません（MUST）。
宣言末尾のセミコロンは許可します。不正文法を宣言の黙った無視で回復してはなりません（MUST NOT）。
XML 属性の重複は不正な XML です。有効な CSS 宣言の重複は第4節で解決します。

許可するプロパティと値（プロパティ名は ASCII の大文字・小文字を区別しない）:

| プロパティ | 受け入れる値の文法 |
| --- | --- |
| fill, stroke | `none`、CSS 基本16色の名前、`#RGB`、`#RRGGBB`、ローカルグラデーションへの厳密な `url(#ID)` |
| stop-color | 同じ色。ただし `none` と URL は不可 |
| opacity, fill-opacity, stroke-opacity, stop-opacity | [0,1] の十進数 |
| stroke-width, font-size | 非負の十進数。任意で `px` |
| stroke-miterlimit | 1 以上の十進数 |
| stroke-dashoffset | 符号付き十進数。任意で `px` |
| stroke-dasharray | `none`、または空でないカンマ・空白区切りの非負十進数リスト。任意で `px`。すべてゼロは不可 |
| fill-rule | `nonzero`、`evenodd` |
| stroke-linecap | `butt`、`round`、`square` |
| stroke-linejoin | `miter`、`round`、`bevel` |
| font-family | カンマ区切りの1個以上の ASCII 名。エスケープ不可。名前は引用符付きの名前か、空白で区切った1個以上の引用符なしの語。引用符付きの名前は一重または二重引用符を使い、区切りの引用符とバックスラッシュを除く印字可能 ASCII を含む。引用符なしの語は `-` で始まってもよい（MAY）識別子（例: `-apple-system`） |
| font-weight | `normal`、`bold`、または 100、200、…、900 |
| font-style | `normal`、`italic`、`oblique` |
| letter-spacing | 符号付き十進数。任意で `px` |
| text-anchor | `start`、`middle`、`end` |
| dominant-baseline | `auto`、`alphabetic`、`middle`、`central`、`hanging`、`text-before-edge`、`text-after-edge` |
| clip-path | `none`、またはローカル clipPath への厳密な `url(#ID)` |
| rx, ry | 非負十進数。任意で `px`。rect のみに適用 |
| marker-end | `none`、または制限付きのローカル marker への厳密な `url(#ID)` |

十進数は `[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)` で、指数表記・非有限値は不可です。
キーワードと色名は ASCII の大文字・小文字を区別せず、フラグメント ID は区別します。
パーサーは CSS をトークン化しなければならず（MUST）、セミコロンでの単純な分割や、
検査前に style ノードを除去する方法で実装してはなりません（MUST NOT）。
その他の関数・単位・パーセント値、currentColor、inherit、initial、unset、revert、
var/calc は拒否しなければなりません（MUST）。この制限は、表内のプロパティに対応する
入力の描画属性にも適用します。形状や変換を含むその他の safe-svg-v1 属性には、
同プロファイルと制限付き描画を引き続き適用します。その他の CSS 形状プロパティと
CSS 変換は受け入れません。rx／ry は SVG2 の CSS 形状の意味に従って解決し、
rect の属性として明示しなければなりません（MUST）。CSS の rx／ry を無視する
レンダラーは、その入力の変換前描画の正しい比較基準にはなりません。

### 3.1 制限付き矢印マーカーの展開

この入力専用サブセットは、図でよく使う矢印の形を扱います。
marker はルート直下の defs の直接の子でなければなりません（MUST）。属性は id、
markerWidth、markerHeight、refX、refY、orient、markerUnits のみです。
幅・高さは正の単位なし十進数（MUST）、refX／refY はビューポート内（MUST）で既定は 0、
orient は `auto`（MUST）です。markerUnits は `strokeWidth`（既定）または
`userSpaceOnUse` です。viewBox、transform、overflow、marker-start／mid、
文脈依存の塗り、再帰的リソース参照は未対応です。各 marker は、d と任意の単色 fill
以外の属性を持たない path をちょうど1個含まなければなりません（MUST）。
形状は、w／h をマーカービューポートの幅・高さとした、領域内の三角形
`M0,0 Lw,h/2 L0,h Z` でなければなりません（MUST）。塗りは単色とし、
none やリソース参照にしてはなりません（MUST）。

marker-end は、fill が none、サブパスが1個の開いた path のみに適用し（MUST）、
絶対座標 M／L／H／V／C の線分を使います（暗黙の座標繰り返しは可能）。
S、Q、T およびすべての相対形式を含むその他の path コマンドは拒否しなければ
なりません（MUST）。最終線分はゼロでない接線を持たなければなりません（MUST）。
L、H、V 線分では接線は線分の方向であり、C 線分では接線は第2制御点から終点への
ベクトルとし、それがゼロの場合は第1制御点から終点へのベクトルにフォールバック
します。終点が両方の制御点と一致する C 線分は拒否しなければなりません（MUST）。
対象 path の transform、opacity、clip-path 宣言は
基準では未対応であり、失敗させなければなりません（MUST）。正規化実装は、最終接線を
計算し、その方向に三角形を向け、strokeWidth 単位なら計算済み stroke-width（既定1）で
拡大縮小し、refX／refY 分をずらし、通常の path／g を対象 path の直後に挿入しなければ
なりません（MUST）。親の合成、ローカル形状、描画順序を保ち、マーカーの塗りと
stroke none を明示し、全使用箇所を展開してから定義・属性を除去しなければなりません（MUST）。
その他のマーカーや対象形状は近似せず拒否しなければなりません（MUST）。
展開数は changes.expanded_markers に報告しなければなりません（MUST）。
出力要素は引き続き safe-svg-v1 の範囲内です。

## 4. カスケード、継承、出力

実装は対応サブセットの作成者カスケードに従わなければなりません（MUST）。
描画属性の詳細度はゼロで、すべての作成者規則より前に置きます。
要素・クラス・ID セレクターの詳細度はそれぞれ (0,0,1)、(0,1,0)、(1,0,0) です。
インライン宣言はすべての対応セレクターより優先します。詳細度が高いものが勝ち、
同じなら style 要素・規則・宣言の後のものが勝ちます。セレクターリストでは、
一致するもののうち最大の詳細度を使います。有効な競合は決定的に解決し（MUST）、
色が違うという理由だけで失敗させてはいけません。`!important` など未対応の競合機構は、
負ける場合でも失敗させなければなりません（MUST）。

勝った宣言は、同じ要素の名前空間なしの描画属性に書き出さなければなりません（MUST）。
継承するプロパティは、その要素自身に勝った宣言がない場合のみ、最も近い祖先の計算値を
継承します。出力は要素階層と属性の配置を保ち、この挙動を維持しなければなりません（MUST）。
同等な継承値を明示してもかまいません（MAY）。特に、グループの opacity と clip-path は
継承する塗りの値ではなく、子に平坦化してはなりません（MUST NOT）。
stop-color／stop-opacity も継承してはなりません（MUST NOT）。宣言も該当する継承も
ない場合は SVG の初期値を使用します。

正規化実装は解決後にのみ style 要素、class、インライン style 属性を除去し、
保持する図形の形状、文字、ID、順序、ローカル参照を保ち（展開するマーカーの管理情報と、
報告したメタデータ移行は除く）、シリアライズ後の出力全体を
safe-svg-v1 で再検証しなければなりません（MUST）。未対応の図形を黙って除去したり、
バイト列を保持した抽出だと主張したりしてはなりません（MUST NOT）。
出力が上限を超えたり、未対応データが残ったりする場合は拒否しなければなりません（MUST）。

## 5. アクセシビリティ情報の移行

各要素のアクセシブルな名前は aria-labelledby、aria-label、既存の直接の子 title の順に
優先します。aria-labelledby と aria-describedby は、空白区切りの一意な ID を順に解決し、
テキストのみの title、desc、text、tspan の内容に対応させなければなりません（MUST）。
これ以外の子孫は不可です。参照先不在、循環・自己参照、非テキストの対象は
失敗させなければなりません（MUST）。参照テキストは空白で連結し、XML 空白を畳みます。
名前は直接の子 title に、aria-describedby の内容は直接の子 desc に表現しなければ
なりません（MUST）。既存の直接の子 title／desc は、置換しない限り保持しなければ
なりません（MUST）。置換が必要な場合は旧テキストを損失として記録しなければなりません
（MUST）。既存の直接の子 title または desc が複数ある場合は未対応です。
新しいメタデータノードの ID を重複させてはなりません（MUST NOT）。

すべての role／aria-* 属性を出力から除去しなければなりません（MUST）。
レポートには、除去した属性ごとに要素位置、値、移行先または明示的な損失理由を
記録しなければなりません（MUST）。優先度の低い aria-label、title／desc では表せない
意味的な役割・状態・関係も含みます。未知の aria-* 属性は黙って破棄せず、
未対応の意味情報として報告しなければなりません（MUST）。
このような意味情報の損失を報告した上で変換に成功してもかまいません（MAY）が、
アクセシビリティの完全な同等性を主張してはなりません（MUST NOT）。
呼び出し側は損失内容を確認する機会を設けることを推奨します（SHOULD）。

## 6. 描画による判定と安全な出力確定

入力検査後にのみ、変換前後を同じ管理されたレンダラーとバージョン、フォント環境、
ビューポート、背景、色・アルファ方針、リソース取得禁止方針で描画しなければなりません（MUST）。
既定の比較はデコード後の RGBA の完全一致としなければなりません（MUST）。
別の明示的なローカル比較方針で文書化した許容差を使ってもかまいません（MAY）が、
その内容を報告し（MUST）、不一致を隠して合格にしてはなりません（MUST NOT）。
OS をまたぐ完全一致は普遍的な要件ではありません。正規化不能、描画失敗、タイムアウト、
不一致は既定で失敗させ（MUST）、成功した正規化 SVG や PNG として出力を確定しては
なりません（MUST NOT）。明示的な解析専用モードで描画を省略してもかまいません（MAY）が、
`not-checked` と報告し（MUST）、検証済み成功を主張せず（MUST NOT）、変換出力を
確定してはなりません（MUST NOT）。テストデータ専用のカスケード検査は、利用者向け実装の
描画判定の代わりにはなりません。

元ファイルは明示的な上書き指定でも変更してはなりません（MUST NOT）。正規化 SVG と
JSON レポートの出力先は別々で、入力や互いの別名であってはなりません（MUST）。
シンボリックリンク・ハードリンクも含みます。既存出力は既定で保持しなければなりません（MUST）。
実装は、出力確定前に完全なデータを一時領域で用意して検証し、上書きしない方法で確定し、
組になる出力の確定に失敗したら新規作成済みの出力を巻き戻さなければなりません（MUST）。
失敗診断を別途返してもかまいません（MAY）が、既存の出力・レポートを上書きしたり、
成功した組の片方だけを残したりしてはなりません（MUST NOT）。将来の明示的な上書き機能でも、
入力を保護し、方針を開示しなければなりません（MUST）。

## 7. 変換レポート

レポートは UTF-8 JSON で、以下の独立した結果を含まなければなりません（MUST）。
下記のフィールド名が基準スキーマを定義し、追加フィールドを設けてもかまいません（MAY）。

| フィールド | 意味 |
| --- | --- |
| profile | `svg-normalization-v1` |
| status | `success` または `failure` |
| input_sha256, output_sha256 | バイト列のダイジェスト。失敗時の出力は null |
| changes | 除去した style 要素、class 属性、インライン style、適用した宣言、expanded_markers の件数 |
| accessibility | 要素パス、属性、元の値、移行先または損失理由を持つ順序付きの記録 |
| checks.input, checks.safe_svg | `pass`、`fail`、`not-checked` |
| checks.render | `pass`、`mismatch`、`error`、`not-checked` |
| checks.container | SVG のみの正規化では `not-applicable`。PNG 変換では別途検査 |
| checks.authenticity | `not-verified`。ハッシュと画素は出自を認証しない |
| render | レンダラーとバージョン、フォント、ビューポート、背景、色・アルファ方針、リソース方針、完全一致／許容差付きの方式と許容差。未検査なら null |
| errors, warnings | コード、段階、説明を持つ構造化記録。該当しなければ空配列 |

失敗コードは invalid-xml、unsafe-input、unsupported-css、invalid-reference、
resource-limit、output-exists、output-alias、render-error、render-mismatch を
区別することを推奨します（SHOULD）。ダイジェストを署名と説明してはなりません（MUST NOT）。
ソースのメタデータを含むレポートは信頼できないデータとして扱わなければなりません（MUST）。
成功レポートは入力・safe-svg・描画検査に合格していなければなりません（MUST）。
構造が正しい PNG だけでは、これらの主張を裏付けられません。
アクセシビリティ記録内のファイルパスは、ルート `/svg[1]` と同名の兄弟内の番号を使用します。
例: `/svg[1]/g[1]/text[2]`。

## 8. テストデータ、移行、将来の CLI（参考情報）

[fixtures/normalization](../fixtures/normalization/README.md) に、独自に作成した合成データ、
期待出力・レポート、拒否例を収録します。利用者の銘板そのものは公開しません。
構造テストと任意の管理された描画テストは依存関係が異なり、有限のデータは完全な認証ではありません。

将来の参照 CLI 案は `normalize input.svg normalized.svg --report report.json` と
`convert input.svg output.png --report report.json` です。この仕様リポジトリでは、
これらのコマンドを実装しません。将来の convert は、正規化の判定後、既存の書き込み処理と
コンテナー検査を実行し、結果を別々に記録しなければなりません（MUST）。
抽出時の自動正規化は提案していません。

このプロファイルは任意の入力経路を追加し、既存データの合否、safe-svg-v1 の許可リスト、
wire v1 を変更しません。既存の読み込み実装は変更不要です。
実装は、対応を主張する前にこのプロファイルをレビューし、固定して参照する必要があります。

参考資料: [CSS カスケード](https://www.w3.org/TR/css-cascade-3/)、
[SVG スタイリング](https://www.w3.org/TR/SVG/styling.html)、
[SVG title/desc とアクセシビリティ](https://www.w3.org/TR/SVG/struct.html)。
上記のサブセットは意図的に狭く定義しています。これらの標準を参照しても、
省略した CSS 機能への対応を意味しません。
