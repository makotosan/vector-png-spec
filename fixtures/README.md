# Interoperability fixtures

`vectors.json` contains base64-encoded tiny PNGs, expected container acceptance,
exact extracted source bytes for accepted cases, and explanations. It includes
positive and negative samples; do not treat every PNG as safe to open in an editor.
Decode a selected PNG with a base64 decoder, or use the standard-library checks:

```sh
python -m unittest discover -s tests -v
python tools/build_fixtures.py --check
```

There are 21 cases: basic, source after IDAT, language fields, BOM, escaped/comment
content, differing preview, unsafe SVG, missing/duplicate source, wrong text type,
compression flag/method, trailing zlib bytes, invalid UTF-8, wrong root, DTD,
processing instructions, conflicting XML encoding, APNG marker, trailing file
bytes and bad CRC. Rebuild after deliberate edits with `python tools/build_fixtures.py`.

`different-preview` is intentionally container-valid with a blue pixel and red
SVG. `unsafe-svg` is container-valid but MUST fail safe-svg-v1. These cases show
why separate validity/security/preview results matter. No unsafe SVG is rendered
by the tools here. The checker validates only this catalog's tiny raster subset;
it is not a complete PNG/SVG validator or a production security component.

The generator uses a fixed stored-DEFLATE block encoding, so fixture bytes are
deterministic across operating systems and zlib versions. `--check` compares the
committed catalog with regenerated bytes. Other conforming writers may choose
different zlib compression and need not reproduce these exact encoded bytes.
Fixtures have no dependency on Pillow, CairoSVG or native apps.
